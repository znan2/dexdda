# 대시보드 피드백 반영 — 2026-09-20

사용자가 승인한 세 가지 개선을 반영했다. .env, 개인키, DRY_RUN, 거래소 수수료 제외 및 업비트 USDT 공통 환산 기준은 변경하지 않았다.

## 저유동성 경로

- 기본 기준은 [설정](../config/settings.toml)의 filters.min_liquidity_usd = 50000이다. 50,000 미만만 저유동성으로 분류하며 경계값 50,000은 포함한다.
- hide_low_liquidity = true가 기본값이다. 코인 전체가 아니라 해당 체인·CA 경로를 기본 화면에서 숨긴다.
- 화면의 **저유동성 포함** 체크박스로 다시 표시할 수 있다. 갭 상한 초과 경로도 먼저 유동성 필터를 적용하므로 의심 목록으로 우회해 나타나지 않는다.
- 레지스트리와 수집 대상은 삭제하지 않는다. 유동성 회복을 계속 관찰하며, 토글은 별도 외부 API 호출 없이 반영한다.
- 알려지지 않았거나 만료된 유동성을 0으로 간주하지 않는다. 체인 선택 보류 또는 일부 체인 미확인으로 구분한다.

## 코인별 체인 비교

별도 브릿지 표를 코인별 비교 목록에 통합했다. 식별은 ticker가 아닌 coin_id이며, 세부 경로의 chain_index·CA·거래소별 route_status를 유지한다.

- 유효한 유동성 중 가장 큰 체인을 대표 가격·표면갭의 기준으로 선택한다. 낮은 유동성에서 나온 큰 갭이 대표 체인을 바꾸지 않는다.
- 일부 체인 유동성이 미확인인 경우 **확인된 최대 · 일부 체인 미확인**으로 표시한다. 전체 체인의 최대라고 주장하지 않는다.
- **경로 비교**를 펼치면 대표 경로와 다른 체인 경로의 가격·갭·유동성·입금망을 비교할 수 있다. 숨겨진 경로도 총 개수에 포함하며, 저유동성 포함을 켜면 나타난다.
- 브릿지 경로는 `매수 체인 → 거래소 입금망 · 브릿지 확인 필요`와 **브릿지 비용·시간 미반영** 문구를 표시한다. 매수 체인에서 거래소로 직접 입금 가능한 것으로 표시하지 않는다.
- 대표 체인과 직접 입금 경로는 주기적으로 가격을 수집한다. 그 외 브릿지 대체 경로는 신선한 가격이 없으면 갭을 비운다. 상세 선택 시 금액별 견적은 별도로 요청한다.
- 의심 목록은 대표 경로가 갭 상한을 넘은 코인이다. 펼친 대체 경로 자체가 상한을 넘으면 해당 경로에 경고를 표시한다.
- 검색·정렬·저유동성 포함·펼침 상태는 자동 갱신 중 유지한다.

API는 기존 main/bridge_candidates/suspected 필드를 호환성용으로 유지하며, 새 화면은 coin_groups를 사용한다. 각 그룹의 routes는 유동성 내림차순이며, low_liquidity/suspected와 거래소별 경로 상태가 포함된다. 기존 필드의 counts는 기존 경로 수이며 새 화면의 코인 수와 다르다.

## 입금 중단·견적 만료

계산 결과와 실행 가능 여부를 분리했다.

- 입금 중단/미확인/최소 입금량 미달이어도 가격·수량·호가·가스 등 계산 근거가 모두 있으면 **입금 가능을 가정한 참고 실효갭**을 별도 색상으로 표시한다.
- API의 result는 계속 null로 유지하고 reference_result/reference_basis에만 참고값을 제공한다. 서버의 실행 가드와 프론트 스왑 버튼은 참고값으로 활성화되지 않는다.
- 가스 누락, 호가 부족, 세율 미확인/양수, 허니팟 의심, 브릿지 비용 미확인에는 참고 실효갭도 만들지 않는다.
- 입금 중단 등 구체적인 사유를 상세 패널 상단에 유지한다. 견적 유효 시간과 만료 안내는 별도 줄에 표시한다.
- 가격 제공자의 시각 오차 허용값을 목록·상세·실행 모두 5초로 통일했다. 실제 OKX 네이티브 가격이 로컬보다 약 2초 빨라 상세의 기존 2초 기준을 넘는 현상을 확인했다. 허용 범위의 미래 시각은 수신 시각으로 제한해 견적 유효기간을 늘리지 않는다. 5초 초과는 사유 표시 후 차단한다.
- 기본 15초 유효기간에서 이미 소요된 시간은 차감한다. 만료 시 숫자를 숨기며, 입금 중단 사유를 만료 문구로 덮지 않는다.
- 견적을 얻기 전 API 오류는 호출 제한 등 구체적인 오류로 표시한다. 이를 단순 견적 만료로 오인하게 표시하지 않는다.
- 갱신은 금액/거래소 변경 또는 **견적 갱신** 버튼으로 수행한다. 자동 상세 재견적 호출은 추가하지 않았다.

## 추가 반영 — USDT 환산값 갱신 지연

USDT는 가격이 없어진 것처럼 표시하지 않고 마지막 정상 관측값으로 목록·상세 갭 계산을 계속한다.

- pricing.usdt_stale_seconds = 300: USDT만 별도 5분 신선도 기준. 다른 코인의 15초 가격 만료는 유지한다.
- WebSocket 수신은 유지하며 정상 USDT 값이 5분간 갱신되지 않거나 오류가 발생하면 REST로 보완한다. 보완 실패도 기존값을 삭제하지 않는다.
- 화면에 마지막 수신 시각과 ‘마지막 정상값 재사용’을 표시한다. 새 정상값이 들어오면 자동으로 바뀐다.
- 상세 USDT 호가 요청이 실패해도 수집기의 마지막 정상값이 있으면 이를 사용하며 fx_cached 경고를 표시한다. 최초 정상 관측 전에는 값을 추정하거나 1달러 고정값으로 대체하지 않는다.
- 마지막 값은 서버 메모리에 보관한다. 서버를 재시작한 직후에는 첫 정상 수신이 필요하다.
- 재사용 값은 대시보드 참고 계산용이다. 실제 실행은 fx_cached 경고 및 별도의 직전 호가 신선도 검사를 통과해야 한다.
- API usdt_krw_ask의 stale과 usable을 구분하고 reused/fresh_seconds를 제공한다. 갭 계산 가능 여부는 유효한 마지막 관측값의 존재로 판단한다.
- Python 239개 테스트 통과. 수신 실패·장기 지연·복구·최초 관측 없음·상세 fallback·스왑 차단을 검사했다. 목록·상세·스왑 브라우저 회귀 검증을 수행했다.


## 추가 반영 — CA 복사·축약 유동성·사용자 기준

- 대표 행과 펼친 체인 행의 **CA 복사**는 해당 행의 전체 컨트랙트 주소를 복사한다. 버튼을 눌러도 상세 견적을 열거나 API를 호출하지 않는다. 상세 패널에도 CA 복사 버튼이 있다.
- 복사 결과에 코인·체인·전체 CA를 표시한다. 클립보드 권한이 없으면 직접 선택해 복사할 수 있도록 전체 주소를 표시한다. 네이티브 자산의 내부 조회용 주소는 CA로 복사하지 않는다.
- 유동성은 소수점 한 자리 이하의 k/m/b 표기로 표시한다. 예: $7,732,863.5533 → $7.7m. 원래 값은 유동성에 마우스를 올리면 확인할 수 있다. 토큰 가격에는 이 축약을 적용하지 않는다.
- 화면의 **최소 유동성**은 million USD 단위다. 기본 1.0m(100만 달러), 입력 범위 1.0~10.0m, 0.1m 단위다. 입력 즉시 목록·경로 수·저유동성 배지·의심 목록에 같은 기준을 적용한다.
- 빈 값, 범위 초과, 소수점 두 자리 입력은 기존 적용값을 유지하고 안내한다. 정확히 기준과 같은 유동성은 포함한다.
- 값은 브라우저 localStorage에 저장하므로 새로고침 후에도 유지한다. 저장 권한이 제한돼도 현재 페이지에서 기준 변경은 동작한다. 브라우저의 표시 설정이며 서버의 설정 파일·거래 가드는 변경하지 않는다.
- **저유동성 포함**을 켜면 선택한 기준 미만 경로도 표시한다. 저유동성 배지는 새 기준을 사용한다.
- 합성 브라우저 검증에 대표/대체 체인/상세 CA의 실제 클립보드 값, 복사 실패 시 수동 복사, $7.7m 축약, 1.1/7.7/7.8/10.0m 필터, 잘못된 입력과 새로고침 복구 검사를 추가했다.

검증 결과: Python 239개 테스트, Ruff 검사, JavaScript 구문 검사 통과. 목록·상세·실행·피드백 Chrome 검증 4종 모두 통과했고, 데스크톱 및 390px 모바일 화면을 확인했다. 실제 거래와 외부 API 호출 없이 합성 데이터로 검증했다.

이번 변경은 정적 화면 파일이므로 실행 중인 서버에서 브라우저를 새로고침하면 적용된다.


## 추가 반영 — 유동성 원인 진단·마지막 정상값 재사용

- OKX 요청 전체 실패(호출 제한, 인증, 연결, 시간 초과 등)와 정상 응답 내 토큰 누락을 구분한다.
- 토큰별로 `token_not_returned`, `value_missing`, `value_invalid`, `source_time_missing`, `source_time_invalid`를 분리한다. 미래 시각은 수집기에서 `timestamp_invalid`로 거절한다. 원문 응답·API 키는 오류에 포함하지 않는다.
- 유동성의 `stale`을 유지하면서 `usable`, `reused`, `age_seconds`, `last_attempt_at_ms`, `error_message`를 제공한다. 0도 정상 유동성이다. 잘못된 값이나 누락으로 기존 정상값을 덮어쓰지 않는다.
- 유동성만 마지막 정상값을 후보 정렬·대표 체인 선택·가격 수집 대상·최소 유동성 필터에 사용한다. 대표 라벨은 ‘관측값 기준 최대’이며 이전값이 포함되면 이를 표시한다. 처음부터 관측 이력이 없던 경로는 값을 만들어내지 않는다.
- 목록과 상세에서 마지막 정상 수신 시각, API 관측 시각, 재사용 여부, 최근 조회 실패 사유·시각을 확인할 수 있다. 원래 관측 시각을 재시도 시각으로 갱신하지 않는다.
- 정상 관측 이력이 없는 단일 체인도 경로 비교를 열어 구체적인 원인을 확인할 수 있다. ‘N개 체인 비교 중’을 ‘N개 체인 · 관측값 없음’으로 바꾼다.
- API diagnostics.liquidity는 신선한 값·재사용 값·미관측 경로 수와 사유별 개수를 제공한다. HTTP 성공과 토큰 데이터 유효 여부는 별개로 진단한다.
- 기존 5분 수집 주기와 15분 신선도 기준은 유지한다. 신선도 초과로 참고값 자체를 삭제하지 않는다. 캐시는 서버 메모리이며 재시작을 넘겨 저장하지 않는다. 재시작 후에는 첫 정상 수집부터 이력이 쌓인다.
- 코인 가격·호가·실제 견적의 신선도 및 실행 검사는 바꾸지 않는다. 오래된 유동성만으로 실제 거래 가능성을 보장하지 않는다.

2026-09-20 읽기 전용 현장 확인: 당시 미확인 82개 경로를 한 배치로 재조회했다. 81개는 토큰 응답 없음, 1개는 유동성 값 없음으로 구분됐으며 요청 실패/호출 제한은 없었다. 이는 해당 조회 시점의 결과다. 이전 정상 관측이 전혀 없는 경로는 이 변경만으로 값이 생기지 않는다.

검증: Python 250 passed. 목록·상세·실행·피드백 Chrome 검사 4종 통과. 재사용 시 기준 필터 유지, 2일 전 관측 시각 표시, 최초 미관측 및 원인별 표시, 단일 미관측 경로 펼치기, 모바일 넘침 없음 확인. 실제 거래는 수행하지 않았다.

이번 변경은 서버 코드도 포함한다. 실행 중인 서버를 재시작하고 브라우저를 새로고침해야 적용된다.


## 추가 반영 — 상대 관측 시각·0.1m 하한

- 유동성의 마지막 정상 수신, API 관측, 최근 조회 시각은 날짜·시간 대신 경과 시간으로 표시한다. 1분 미만은 ‘방금 전’, 1시간 미만은 ‘N분 전’, 24시간 미만은 ‘N시간 전’, 이후 ‘N일 전’이다. 각 단위는 내림하며 원본 타임스탬프는 API에 유지한다.
- 목록 갱신 시 상대 시각을 다시 계산하고, 상세 패널을 열어 둔 동안에도 경과 시간을 갱신한다.
- 최소 유동성 입력 범위를 0.1~10.0m로 확장했다. 0.1m는 100,000 USD이며 0.1m 단위로 입력한다. 기존 기본값 1.0m 및 저장된 유효한 선택값은 유지한다. 0.5m도 입력·저장 가능하다.
- 2026-09-20 로컬 진단 재확인: 유동성 요청 20회 성공·0회 실패, 정상 경로 830개, 최초 미관측 82개(토큰 응답 누락 81개·유동성 값 누락 1개). 수집은 5분마다 재시도하지만 공급자 응답 누락은 기다림만으로 해결된다고 볼 수 없다.
- 이번 변경은 정적 화면 파일만 수정했으므로 브라우저 새로고침으로 적용된다.


## 추가 반영 — 기본 숨김·블랙리스트·입출금 갱신

미관측 유동성/입금 중단 경로 기본 숨김, 영구 블랙리스트 및 수동 입금망 제외, 30초 상태 조회를 구현했다. [사용법과 검증](dashboard-controls.md)을 참고한다. 서버 재시작이 필요하다.


## 견적 표시 유지 (2026-09-20)

상세 견적은 10초 유효시간이 지나도 실효갭·예상 손익·수령량을 유지한다. 남은 유효시간 대신 `N초 전 갱신`을 표시하고 1분/1시간/1일 경과 시 해당 단위로 전환한다. 입금 중단·조회 실패 사유는 그대로 보존한다. 다른 코인·금액·거래소로 바꿀 때는 이전 계산을 무효화한다.

화면 표시만 연장하며 내부 만료 시각, 만료 후 실행 준비 차단, 서버의 신규 견적 및 실행 검사는 그대로 유지한다. 브라우저 회귀 검증에서 유효한 견적의 실행 준비가 활성화되었다가 만료 후 비활성화되고 숫자는 남는 것을 확인한다.

BREV 공개 읽기 전용 확인: Ethereum의 토큰 단위 시세는 약 $0.062223, 100 USDT 견적은 약 1,241.48 BREV/-22.72%, 1,000 USDT 견적은 약 12,415.41 BREV/-22.72%, 경로는 JIT Router, 토큰세는 API 기준 0. 추가 원본 견적에서는 기준가격 $0.062223, 평균 매수가 약 0.080616 USDT, 가격 영향 -22.79%를 확인했다. 각 값은 조회 당시 값이다.

OKX `priceImpactPercent`는 `(수령 가치 - 지불 가치) / 지불 가치`이며 토큰 단가는 참고 시세다. 따라서 위 결과는 주문 규모가 풀 가격을 22.7% 이동시켰다는 증거가 아니라 기준 시세와 실행 견적 사이의 괴리가 큰 사례로 해석해야 한다. 실제 풀 깊이·참고 시세 산출 경로 문제의 근본 원인은 이번 조회만으로 확정하지 않았다. 매수금액 변경에 따른 예상 체결가 비교가 총유동성 숫자만 보는 것보다 직접적인 확인 방법이다.

## 브릿지 경로 가격 영향 조회 (2026-09-20)

- 자동 순환 견적은 추가하지 않고 기존 상세 패널 조회 방식을 유지한다.
- 선택한 거래소의 route_status가 bridge_candidate이면 매수 체인의 OKX quote만 요청한다. 지갑 상태/입금 조건/승인 정보/네이티브 가격/RPC/거래소 호가/USDT 환산값을 추가 조회하지 않는다.
- 가격 영향은 OKX priceImpactPercent 원값을 표시하며, 실제 수령량과 라우팅을 함께 보여 준다. 실효갭/참고 실효갭/가스/호가 결과는 생성하지 않고 관련 화면도 생략한다. 실행은 계속 불가하다.
- 견적 만료 후에도 가격 영향과 수령량은 유지하고 상대 갱신 시간을 표시한다. 금액 변경 시 재조회하고, 실패 사유는 브릿지 안내에 가려지지 않도록 표시한다. API가 가격 영향을 제공하지 않으면 미확인으로 남긴다.
- CAP의 BNB Chain 견적에 필요한 Binance-Peg USDT를 config/quote_assets.toml에 추가했다. CA: 0x55d398326f99059ff775485246999027b3197955, decimals=18. simple_gas=false로 유지한다. 매수 자산이 미등록된 다른 체인은 기존처럼 조회 사유를 표시한다.
- 근거: https://docs.bnbchain.org/bnb-smart-chain/benchmark/design-reference/ 의 BEP20 계약 링크. 공식 공개 RPC https://bsc-dataseed.bnbchain.org 에서 eth_chainId=56, decimals()=18, symbol()=USDT를 읽기 전용으로 확인했다.
- 실제 CAP(cap-4) BNB Chain 1,000 USDT 단일 조회: 가격 영향 -0.10%, 예상 수령량 22083.928610655833905869, errors=[], result/gas/book=null, execution_enabled=false. 시점별로 달라지는 견적이며 브릿지 비용이나 실효 수익률을 나타내지 않는다. 서명/거래 전송 없음.
- 검증: 전체 pytest 275개 통과, Ruff 통과. check_feedback_ui.cjs 및 check_detail_ui.cjs 통과(브릿지 금액 변경/만료 유지/오류/모바일, 기존 실효갭 회귀). 합성 화면: docs/screenshots/bridge-impact-desktop.png, bridge-impact-mobile.png.
- 반영: 실행 중인 백엔드 재시작 후 브라우저 새로고침 필요.


## 상세 견적 수동 갱신 (2026-09-20)

- 상세 패널을 열거나 다시 열어도 견적 API를 호출하지 않는다. 금액·매수 자산·거래소 변경도 자동 조회하지 않는다.
- 사용자가 견적 갱신 버튼(또는 폼 제출)을 요청한 경우에만 현재 설정으로 1회 조회한다. 진행 중 중복 제출은 무시하며 자동 재조회 큐를 제거했다.
- 설정을 바꾸면 기존 결과와 실행 가능 상태를 즉시 무효화한다. 이미 진행 중인 이전 요청은 끝나도 표시하지 않고 다음 수동 갱신을 기다린다.
- 화면 안내를 수동 갱신에 맞게 변경했다. 브라우저 새로고침으로 적용된다.
- 검증: check_detail_ui/check_assets_ui에서 열기·설정 변경 시 요청 0회, 버튼 클릭당 1회, 지연된 이전 응답 폐기 및 자동 재조회 없음 확인. check_feedback_ui/check_execution_ui도 통과, 브라우저 오류 0.

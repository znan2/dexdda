# 갭 모니터

최신 변경: [저유동성 필터·코인별 비교](dashboard-feedback.md).

명령은 저장소 루트에서 실행한다.

```sh
uv run dexdda
```

[대시보드 열기](http://127.0.0.1:8000). 서버를 종료하려면 터미널에서 Ctrl+C를 누른다.
별도 프론트 빌드나 npm 설치는 필요 없다. 이미 서버가 실행 중이었다면 재시작하고 브라우저를 새로고침한다.

## 화면

- 메인 표: 티커, OKX 토큰명·거래소 한글명, DEX 체인·가격, 업비트/빗썸 표면갭, 입출금 상태.
- 기본 정렬: 두 거래소의 계산 가능한 갭 중 큰 값 내림차순. 0%도 유효한 값이며, 계산 불가 행은 아래에 표시한다.
- 선택 정렬: 업비트 갭, 빗썸 갭, 티커 순.
- 검색: 티커·이름·coin_id·체인·전체 CA를 검색한다. 기존 목록에서만 필터링하며 외부 토큰을 추가하지 않는다.
- 직접 입금·브릿지 경로를 coin_id별로 묶고 유동성 최대 체인을 대표 표시한다. 경로 비교와 의심 목록은 펼칠 수 있다. 저유동성 포함·검색·정렬·펼침 상태를 자동 갱신 중 유지한다.
- 브릿지 선택 보류 행에도 알려진 거래소 입금망을 표시한다. 선택하지 못한 체인과 가격은 대시로 표시한다.
- 상단은 업비트 USDT/KRW 매도 1호가, 경로 수, 브릿지 선택 보류 수, 의심 목록 수, 마지막 갱신 시각과 DRY_RUN 설정을 표시한다.
- 모바일에서는 표 영역을 가로로 스크롤한다. 전체 페이지가 가로로 밀리지 않는다.

같은 coin_id의 경로를 묶으며 ticker 문자열만으로 다른 코인을 합치지 않는다. coin_id·체인 ID·컨트랙트 주소를 유지하며, 전체 주소는 행의 식별 정보에 마우스를 올려 확인할 수 있다.
API 수집기가 레지스트리 항목을 순회해 행을 생성하므로 외부 응답에만 있는 토큰을 표시할 경로가 없다.

## 상태 해석

입금 중단은 메인 목록 제외 조건이 아니다. 배지로 표시하며 네트워크 미지원과 구별한다.

| 원본 wallet_state | 화면 |
|---|---|
| working | 입출금 정상 |
| withdraw_only | 입금 중단 |
| deposit_only | 출금 중단 |
| paused | 입출금 중단 |
| unsupported | 미지원 |
| 그 외 | 상태 미확인 |

상태는 거래소별 지원망을 이름과 함께 표시한다. 여러 지원망이 있으면 모두 표시하므로, DEX 체인과 다른 지원망도 있을 수 있다.
입출금 상태는 M1 레지스트리 스냅샷 기준이며 실시간 상태 확인은 M4에서 다룬다.
브릿지 후보의 정상 입출금 배지는 그 거래소 지원망의 상태를 뜻하며, 표시된 DEX 체인의 직접 입금 가능 여부와는 다르다.
해당 행에는 별도로 직접 입금 불가/브릿지 필요를 표시한다.

업비트 USDT 기준, 1 USD≈1 USDT 가정, 거래소 수수료 제외를 화면에 명시한다.
표면갭은 슬리피지·가스·체결 수량을 반영한 실효갭이 아니다. 모든 행은 조회 전용이다.
DRY_RUN 꺼짐도 실제 설정대로 표시하지만 M3에는 거래 실행 기능이 없다.

## 갱신과 오류

- `[pricing] ui_poll_seconds`를 사용하며 기본 2초다. 브라우저는 0.5~60초 범위로 제한한다.
- `/api/gaps`만 조회한다. 화면 요청은 외부 가격 API 호출을 추가로 발생시키지 않는다.
- 자동 요청은 중첩하지 않으며, 새로고침 버튼으로 즉시 다시 조회할 수 있다.
- API 연결 실패/503은 연결 상태와 안내문에 표시하고 자동 재시도한다.
- USDT는 별도 5분 신선도 기준과 마지막 정상값 재사용을 적용하고 수신 시각을 표시한다. 다른 종목은 마지막 수신 시각을 기준으로 만료된 가격·갭을 대시로 바꾼다. 요청이 지연되거나 서버가 끊겨도 브라우저 타이머가 만료를 적용한다.
- 서버에서 stale인 데이터는 화면에서 다시 유효한 것으로 계산하지 않는다. 갭은 서버 계산값만 표시한다.
- 외부 이름·메시지를 HTML로 삽입하지 않고 textContent로 표시한다.

## 구현과 검증

화면 파일: `src/app/web/index.html`, `dashboard.css`, `dashboard.js`.
서버는 `/assets`에서 이 정적 디렉터리만 제공한다.
화면을 위해 API에 `token_name`, `chain_name`, `ui_poll_seconds`, 필터 설정과 보류 후보의 지원망을 추가했다.

```sh
uv run pytest -q
uv run ruff check src tests scripts
uv run ruff format --check src tests scripts
node --check src/app/web/dashboard.js
```

브라우저 검증에는 Node.js, Playwright 모듈, 설치된 Google Chrome이 필요하다.
이는 검증 도구의 의존성이고 대시보드 실행에는 필요하지 않다.

```sh
# Playwright가 기본 모듈 경로에 설치되어 있으면:
node scripts/check_ui.cjs
# 실제 API까지 확인하는 약 32초 읽기 전용 검증:
node scripts/check_ui.cjs --live
```

별도 런타임에 설치된 Playwright를 쓸 때는 `NODE_PATH`에 해당 node_modules 경로를 지정한다.
검증 스크립트는 임시 포트의 로컬 서버와 독립 Chrome 프로필을 만들고 종료 시 둘 다 정리한다.
일반 검증은 합성 fixture로 동작하고 .env나 외부 API를 읽지 않는다. --live는 기존 서버처럼 .env를 읽어 가격을 수집하므로 상시 서버와 중복 실행하지 않는다.

검증 결과: [M3 검증 기록](m3-verification.md).

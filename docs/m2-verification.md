# M2 검증 기록

2026-09-19, 사용자 API 수정 후 기존 M1 레지스트리로 검증했다. .env와 레지스트리는 변경하지 않았다.

## 자동 검증

- `uv run pytest -q`: 137개 통과.
- 김프 1%·실제 환율 기준 코인 프리미엄 1%일 때 USDT 환산 갭 0%.
- 업비트/빗썸 공통 업비트 USDT 매도 1호가 사용, 별도 거래소 갭, 거래소 수수료 제외.
- Decimal 정밀도, NaN·Infinity·0·음수 거부, 오래된 값·역순 데이터·미래 시각 차단.
- 브릿지 최대 유동성 체인 하나, 동률 순서, 불완전 비교 시 보류, 유동성 복구 후 선택.
- ±30% 초과 양방향 의심 분리, 하한·인식 정보 경고/숨김, 제외 경로 미조회.
- OKX 부분 누락·요청 실패의 격리, 공유 게이트 직렬화 및 호출 제한 대기.
- WS 정상값 우선, stale REST 보완, WS 단절·재연결, REST 실패 중 새 WS 값 보존.
- 워커 취소·연결 정리, API 분류/캐시/503, 원문 예외·비밀값 비노출.
- 기존 M0/M1 테스트 포함.

## 실제 API 조회

OKX 가격 및 유동성 엔드포인트에 각각 100개 토큰 배치를 요청해 99개 응답을 확인했다.
두 엔드포인트의 일부 누락을 정상 토큰과 분리해 처리한다.
업비트와 빗썸 최신 WebSocket 주소에서 ticker 프레임을 수신했다.

`uv run scripts/check_prices.py --seconds 35` 실행 결과:

검증 구간에서 OKX 가격 22회·유동성 10회, 업비트 REST 9회·빗썸 REST 22회가 성공했다.
양 거래소 WS 수신도 성공했고 기록된 제공자 요청 실패는 없었다.
최종 CEX 값의 출처는 업비트 WS 103개·REST 100개, 빗썸 WS 45개·REST 317개였다.
거래가 뜸한 종목도 정상 REST 재조회로 수신 신선도를 갱신하며, 요청 중 더 최신 WS가 들어오면 WS 값을 유지한다.
가격 한 순회는 약 6.5초, 초기 전체 유동성 조사는 약 21초였다.
위 결과는 한 시점의 관측값이며 모든 종목의 가격 제공, 지속 신선도, 장기 쿼터를 보장하지 않는다.

거래·approve·전송·입금 주소 생성·자동 결제는 하지 않았다. DRY_RUN과 관계없이 실행 API가 없다.

## 추가 통합 확인

- 실제 uvicorn을 127.0.0.1 임시 포트에 띄워 /api/gaps 200, 외부 Host 400, /api/swap 404를 확인하고 프로세스를 종료했다.
- 빗썸 REST timestamp에서 9시간 오프셋을 발견해 응답의 UTC 필드로 검증 후 정규화했다. WebSocket 없이 BTC·ETH REST만 조회한 확인에서도 두 가격 모두 fresh로 판정됐다.
- 이미 UTC인 빗썸 응답, 9시간 오프셋 응답, UTC 필드 불일치 거부를 합성 테스트로 고정했다.
- lint 및 format 검사 통과. uv sync --locked --offline 통과.
- 기존 registry.json/registry_report.md SHA-256이 M1 검증 기록과 일치한다. .env 권한 0600 유지.

M2 완료 기준을 충족했다. M3 UI는 시작하지 않았다. 검증 프로세스는 모두 종료했다.

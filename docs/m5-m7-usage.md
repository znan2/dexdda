# 스왑·입금 주소·운영 기능 사용 안내

M5~M7 필수 기능을 구현했다. 실제 자금으로 스왑하는 검증은 계획대로 사용자가 소액으로 직접 수행하며, 에이전트는 DRY_RUN을 끄지 않았다.

## 실행과 현재 상태

명령은 저장소 루트에서 실행한다.

```sh
uv sync --locked
uv run dexdda
```

http://127.0.0.1:8000 에서 종목을 선택하고 금액·매도 거래소를 설정한다. 유효한 실효갭과 직접 입금 경로가 있으면 **DRY_RUN 실행 준비**를 누를 수 있다. 이 버튼은 먼저 최신 데이터와 잔고를 검사하고 확인 모달을 연다. 모달을 열기만 해서는 승인·스왑이 시작되지 않는다.

DRY_RUN에서도 USDT·네이티브 가스 잔고, RPC, 경로·입금 상태·가격 조건을 검사한다. 잔고가 없거나 갭이 최소값에 미달하면 정상적으로 차단된다. 개인키는 DRY_RUN에 필요하지 않다. 확인 후에는 승인 reset·approve·swap 계획만 표시하며 서명과 전송은 모두 0회다.

현재 레지스트리의 조회 대상은 29개 EVM 체인이다. 매수 자산은 12개 체인의 USDT/USDT0 주소를 검증했다. 완전한 체인 비용 모델이 있는 Ethereum(1), Polygon(137), Avalanche C(43114)만 실행 경로를 열 수 있다. 해당 RPC·잔고·입금 가능 상태도 갖춰져야 한다. 다른 체인은 목록·가능한 견적 조회를 유지하고 비용 검증 전 실행을 차단한다. 28개 체인의 컨트랙트 검토 목록은 28개 체인의 실행 준비 완료를 뜻하지 않는다.

브릿지 후보는 계속 조회 전용이다. 거래소 전송·매도는 자동화하지 않았다.

## 거래 설정

`config/settings.toml`의 `[swap]`에서 다음 값을 변경하고 서버를 재시작한다. 구현용 기본값이며 사용자의 실거래 허용 금액을 확정한 것은 아니다.

| 설정 | 기본값 | 의미 |
|---|---|---|
| max_amount_usdt | 1000 | 한 번에 매수할 수 있는 최대 USDT |
| min_gap_percent | 0 | 직전 비용 반영 실효갭의 최소값 |
| slippage_percent | 0.5 | DEX 최소 수령량에 적용할 허용 슬리피지(%) |
| approval_policy | capped | capped는 유한 상한 승인, exact는 매수 금액만 승인 |
| approval_cap_usdt | 5000 | capped 정책의 승인 상한. 무제한 승인은 사용하지 않음 |
| confirmation_seconds | 60 | 확인 모달의 유효 시간 |
| receipt_timeout_seconds | 120 | 영수증을 기다리는 시간. 초과해도 실패로 단정하지 않음 |
| receipt_confirmations | 2 | 승인·스왑 영수증의 확인 블록 수 |

모달은 코인 풀네임, 체인, 전체 CA와 앞뒤 6자리, 금액, 슬리피지, 예상·최소 수령량, 승인 횟수·상한, 가스 예산, 직전 실효갭을 표시한다. 실제 실행 모드는 사용자가 개인키와 DRY_RUN을 직접 설정하고 재시작한 경우에만 활성화되며, 이 모드에서도 매번 확인이 필요하다.

견적, 입금 상태, 잔고, allowance, nonce는 확인 후 다시 검사한다. approve가 필요하면 먼저 승인하고, 그 뒤에도 스왑 견적과 가드를 다시 확인한다. 이미 승인한 비용이 수익 계산에서 빠지지 않도록 승인 예산을 유지한다. 가스가 확인한 상한보다 증가하거나 최소 수령량이 악화되면 중단하고 새 확인을 요구한다.

업비트·빗썸 모두 **업비트 KRW-USDT 매도 1호가**로 환산하며 **거래소 매매 수수료는 제외**한다. OKX의 USD 네트워크 비용에는 1 USD≈1 USDT 가정을 적용한다. 실행 확인의 스왑 비용은 OKX 네트워크 비용과 RPC 가스 예산 중 큰 값을 사용하고, 승인·전송 예산은 별도로 더한다. 따라서 M4의 일반 추정치와 확인 모달의 보수적인 실효갭이 다를 수 있다. 전송 예산은 실제 수신 주소에 대한 시뮬레이션 결과가 아니다.

## 중단·재시작과 실행 이력

화면 아래 **스왑 이력**에서 기존 작업을 다시 연다. **상태 다시 조회**는 이미 기록한 해시의 영수증과 수령량을 조회하며 새 거래를 보내지 않는다.

| 상태 | 처리 |
|---|---|
| DRY_RUN 완료 | 승인·스왑 계획 확인 완료. 실제 거래 없음 |
| pending / 영수증 시간 초과 | 기존 해시의 결과를 계속 확인. 새 실행은 차단 |
| submission_unknown | RPC 응답이 불확실함. 해시는 전송 전에 저장되어 있으며 자동 재전송하지 않음 |
| nonce_conflict | 외부 지갑 사용 등으로 nonce가 바뀜. 새 견적 필요 |
| approval_complete_reconfirm | 승인만 끝난 채 중단됨. 현재 가격으로 새 확인 필요 |
| reverted | 해당 거래 실패. 다음 단계 전송 중단 |
| success + history_pending | 온체인 스왑 성공, 실제 수령량 집계 대기. 조회 실패를 스왑 실패로 바꾸지 않음 |

미확정 거래 기록을 지워서 가드를 우회하지 않는다. 체인에서 교체·취소한 거래도 자동으로 추정해 재전송하지 않으며, 기존 nonce·해시 결과를 먼저 확인해야 한다.

이력은 `data/swap_history.json`, 구조화 운영 로그는 `data/operations.jsonl`에 저장한다. 지갑·주소가 포함되는 로컬 캐시와 이력은 권한 600 및 Git 제외로 관리한다. 개인키·API 키·JWT·RPC URL·원문 예외·서명된 raw transaction은 이력/로그에 저장하지 않는다. 이벤트 로그는 허용한 상태 코드와 필드만 기록한다.

## 전체 입금 주소 사전 준비

2026-09-20 기준 레지스트리의 직접 입금 가능한 **거래소·코인·네트워크 조합 472개가 모두 준비됨**을 확인했다. 브릿지 후보의 직접 입금 불가 체인은 포함하지 않는다.

```sh
# 기존 주소 조회·동기화만
uv run scripts/sync_deposit_addresses.py --read-only

# 전체 대상 동기화: 없는 주소만 생성 요청 후 조회
uv run scripts/sync_deposit_addresses.py
```

최초 사전 준비는 완료했다. 레지스트리 재빌드 또는 계정/API 키 변경 뒤에는 다시 동기화한다. 이미 있는 주소는 재생성하지 않는다. 비동기 생성은 대기 상태를 저장하고 재실행 시 먼저 조회한다. 인증·권한 오류는 생성 요청을 중단하고 사유를 집계한다.

캐시는 `data/deposit_addresses.json`에만 저장하며 스크립트는 주소 값 없이 상태별 개수만 출력한다. 거래소 API 키 식별자가 달라지면 이전 계정의 주소를 재사용하지 않는다.

스왑 성공 화면은 실제 수령량과 **스왑한 체인에 대응하는 net_type의 주소만** 보여준다. 주소가 없거나 현재 매핑·계정과 다르면 비워 두고 사유를 표시한다. 입금 상태를 새로 조회하고, 입금 가능 상태에서 주소·메모 복사 버튼을 제공한다. 복사 뒤 주소 앞뒤 6자리를 크게 표시한다. 업비트 입출금 상태는 지연될 수 있다는 문구를 함께 표시한다. 주소 표시·복사는 거래소로의 자동 전송이 아니다.

## 운영 정보

- 30분마다 거래소 마켓과 레지스트리를 비교한다. 미등록 마켓은 **레지스트리 재빌드 필요** 알림으로 표시한다. 자동으로 식별·등록하지 않는다.
- 서버를 종료한 상태에서 `uv run scripts/build_registry.py`로 재빌드하고 검토 리포트를 확인한다. 이후 주소 동기화를 실행하고 서버를 재시작한다.
- 참고 김프는 업비트 USDT ask와 ECB USD/KRW 교차환율을 비교한다. ECB는 일일 참고값이므로 날짜와 지연 여부를 표시한다. 이 값은 실효갭·스왑 가드에 사용하지 않으며 조회 실패도 분리한다.
- 유료 API 전환은 보류 상태다. 결제·요금제 변경을 자동으로 수행하지 않는다.
- Solana, MEV/Broadcast, 다른 DEX 통합은 계획서의 선택 확장 항목으로 남긴다.
